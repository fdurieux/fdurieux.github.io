A programme · shift-left quality for the information upstream of code

Legible.

Everything that comes before code, from requirements and processes to models, decisions and contracts, made query-able for humans and AI, and checked before it is handed to a developer or a dev-agent.

Maintained by fdurieux. The page is a map: it names the artefacts, the tools and practices that already gate them, the projects started to fill the gaps, and the gaps that stay open. Where a claim is backed by a measurement it says so; where it is a mechanism we expect to work, it says that too.

Why this, and why now

Code has had quality gates for twenty years: a linter runs on every change, a severity threshold fails the build, and a baseline lets an old codebase adopt the rule without a clean-up project. The information that code is built from has had none of that. Requirements sit in documents, processes in a modelling tool, architecture in slides, decisions in people's heads. Each is checked by whoever chooses to read it.

Two things changed. First, code is now generated from that information by AI agents at near-zero cost, so its defects reach production faster and in volume. Second, the quality of what the agent is given turns out to decide the quality of what it produces. On one controlled instrument, where the diagram was the only input the generator had, code generated from sequence diagrams degrades sharply below a measurable maturity level and improves with it above that level measured. Given contracts and examples beside the diagrams, the same diagrams fixed the layout and the interfaces of the code and changed none of its behaviour measured. On the industry's reference benchmark, a large share of real issue descriptions had to be hand-graded as under-specified because no machine check exists for them research. Repairing the input measurably raises the pass rate of the generated code research.

So the foundation of a semantic transformation, where an organisation's intent becomes something a person or an agent can query rather than re-read, is also a quality problem. Information that is not well-formed cannot be queried reliably, and information that has not been checked should not be handed on. This programme treats the two halves as one.

Legible

Query-able by humans and AI. Concretely: one identity per entity across every artefact that names it, stable identifiers that other artefacts can reference, machine-readable forms beside the human ones, and traceability that can be walked in both directions, from a requirement to the model that realises it and the test that proves it.

Checked

Gated before hand-off. A deterministic check runs on every change, at the author's desk first and in the pipeline second. Findings carry a severity, a threshold fails the build, a baseline lets a brownfield estate adopt the gate without a big-bang clean-up, and a graded score shows progress rather than a yes or no.

The gate contract

Every tool in this programme, and every third-party tool the map calls "covered", is measured against the same six properties. They are what separates a check that changes behaviour from a report that ages in a shared folder. Projects that lacked them are why the research tools of the last fifteen years are dormant: single author, grant lifetime, an IDE plug-in, no exit code.

  1. Exit codes 0, 1, 2. Clean, findings at or above the threshold, could not run. A pipeline needs nothing else to stop.
  2. A severity ladder and a threshold. Findings carry blocker, critical, major, minor or info; one flag sets where the build fails.
  3. A baseline and a ratchet. Record today's state once, fail only on regression, never update the baseline from inside the gate.
  4. A machine-readable report. JSON pinned by a published schema, and SARIF so findings appear in the code host without a plugin.
  5. Runs anywhere. No runtime dependencies, a pre-commit hook, an editor integration, and a CI action.
  6. Evidence tagging. Every claim a project makes about its value is marked measured, mechanism or hypothesis, and the measurement is published, failures included.

Projects

Two exist. The others are planned, in the order their feasibility was assessed, and each stays "planned" until a repository exists. A planned project is a statement of intent, not a tool.

pumllint

shipping

A linter and maturity scorer for PlantUML diagrams. The reference implementation of the gate contract, with the measured evidence behind the programme's central claim.

aris2puml

shipping

Converts ARIS process exports to PlantUML activity diagrams so pumllint can gate them. Makes a process checkable; never makes it pass.

Cross-artefact identifier gate

planned

One identifier graph across requirements, models, tests and API operations; fail on orphans and unknown references. Builds on pumllint's trace command.

Requirements wording linter

planned

Deterministic INCOSE and EARS rules with severities and a baseline. Ambiguity detection is reported, never gated, because its precision is too low to block a build.

EPC toolchain in the open

planned

An EPML reader and an EPC conventions ruleset, so process models from any tool that writes the interchange format can be gated.

BPMN repository-wide checks

planned

Cross-model references, pragmatic modelling guidelines and a score, as a bpmnlint plugin.

What a gate can and cannot tell you

A gate answers three questions with decreasing confidence. Is the artefact well-formed and precise? Fully mechanisable, and what the tools above do. Does the design satisfy a property someone stated, such as "every path reaches an end" or "payment never precedes approval"? Mechanisable for process and state models, with the property written by a person. Is the design the right one for the people it serves? Not mechanisable. Every automated check compares an artefact with another artefact; when both are wrong, agreement proves nothing. That question is answered by stakeholders in the room, by a walking skeleton, and by measuring the shipped product. AI reviewers can generate the questions for that room; the 2026 evidence on their agreement with human architects is too weak to let them close it.

Evidence tags. measured a controlled experiment, published with its failures; the pumllint record is in EVIDENCE.md. research peer-reviewed or industry-primary work by others. mechanism a stated causal chain, not yet measured. The tool survey behind the table was made on 2026-10-26; tool states move, and a correction is a pull request on this page.
